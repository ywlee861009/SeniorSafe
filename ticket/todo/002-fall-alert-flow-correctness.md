# 할일-002 낙상 알림/취소 플로우 정합성 수정

## 우선순위

P0

## 문제

문서상 플로우는 어르신이 30초 안에 취소하면 보호자에게 알림을 보내지 않는 방식입니다. 현재 Android 화면은 카운트다운이 끝난 뒤에야 낙상 이벤트를 보고하므로, 카운트다운 중 취소 버튼을 눌러도 백엔드에는 취소할 이벤트가 없습니다. 반면 백엔드는 `/fall/cancel`을 제공하고 있어 “먼저 보고 후 취소” 모델을 암시합니다. 제품 동작 계약을 하나로 정해야 합니다.

## 작업 범위

- 표준 플로우 결정:
  - A안: Android가 30초 대기 후 `/fall/event` 전송. 전송 전 취소는 백엔드 취소 API를 쓰지 않는다.
  - B안: Android가 즉시 `/fall/event`를 pending 상태로 전송. 취소 시 `/fall/cancel` 전송. 백엔드는 취소 윈도우 종료 전까지 FCM을 지연하거나 억제한다.
- 선택한 플로우에 맞춰 API, 백엔드 서비스, Android ViewModel, 문서 수정.
- 카운트다운 화면이 이미 떠 있을 때 센서 중복 감지가 다시 발생하지 않도록 처리.
- 현재처럼 예외를 조용히 무시하지 않고 보고/취소 실패 상태를 UI 또는 로그로 드러낸다.

## 완료 조건

- 취소 버튼이 의도한 백엔드 상태를 만든다.
- 취소된 오감지는 보호자에게 알림이 가지 않는다.
- 낙상 이력에서 보고됨/취소됨 상태가 명확히 구분된다.
- 취소한 경우와 취소하지 않은 경우의 수동 테스트 절차가 문서화된다.
