# 할일-008 낙상 감지 알고리즘 검증

## 우선순위

P1

## 문제

가속도 센서 기반 상태 머신은 구현되어 있지만, 현재 threshold와 시간값은 실제 생활 움직임 기준으로 충분히 검증되지 않았다. 이 제품에서는 오탐과 미탐 모두 위험도가 높다.

2026-05-16 현재 Android MVP에는 검증을 위한 런타임 진단 기반이 추가되어 있다.

- 낙상 감지 런타임은 `core:fall-detection` 모듈에 있다.
- MVP 진단 로그는 `core:diagnostics` 모듈의 Room DB에 저장된다.
- MVP 화면은 최근 로그를 Runtime Log 콘솔로 표시한다.
- 서비스 생존 여부는 저장된 boolean이 아니라 1초 heartbeat와 5초 stale 기준으로 표시한다.
- 앱 화면을 kill해도 foreground service가 살아 있으면 센서 샘플과 상태 전이 로그가 계속 DB에 남는다.
- OS가 서비스를 강제 종료하면 heartbeat가 끊기며 UI는 최대 5초 뒤 `보호 꺼짐`으로 동기화된다.

남은 검증 포인트는 알고리즘 자체다. 특히 현재 `STILL_THRESHOLD`는 `magnitude < 3.0` 기준이라, 휴대폰이 바닥에 정지해 있어도 중력값 때문에 실제 정지를 잘못 판단할 수 있다. 정지 판단은 magnitude 절대값이 아니라 9.8 근처 안정성 또는 최근 샘플 변화량/분산 기반으로 재설계해야 한다.

## 작업 범위

- 휴대폰 위치와 활동별 반복 가능한 수동 테스트 프로토콜 작성.
- 걷기, 앉기, 휴대폰 떨어뜨림, 낙상 시뮬레이션의 가속도 trace 수집.
- 자유낙하, 충격, 정지 threshold 튜닝.
- 감지 후 debounce/cooldown 추가.
- 페어링 전/후 낙상 감지 동작을 정의한다.
- 프로세스 종료나 앱 재시작 이후 서비스 상태와 최근 이벤트 상태 유지 검토.
- MVP Runtime Log로 수집한 trace를 기준으로 threshold와 상태 전이 조건을 조정한다.
- 앱 화면 kill, service 생존, OS/service kill, service restart 케이스별 로그와 UI 상태 동기화를 수동 검증한다.

## 완료 조건

- threshold 선택 이유가 테스트 데이터와 함께 문서화된다.
- 주요 오탐 케이스의 기대 동작이 정리된다.
- cooldown 동안 중복 알림이 방지된다.
- 앱 재시작 후에도 서비스 상태를 사용자가 이해할 수 있다.
- Runtime Log 기반으로 최소 걷기/앉기/휴대폰 낙하/낙상 시뮬레이션 trace가 남아 있다.
