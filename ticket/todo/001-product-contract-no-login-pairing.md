# 할일-001 로그인 없는 페어링 제품 계약 확정

## 우선순위

P0

## 문제

현재 앱과 백엔드는 로그인, 사용자 role, access token, 보호자-어르신 계정 관계를 전제로 구현되어 있다. 새 기획에서는 앱을 설치하면 바로 보호자/어르신 모드를 선택하고, 연결 코드로 서로 페어링해서 사용해야 한다.

## 작업 범위

- MVP 사용자 흐름을 문서로 확정한다.
  - 앱 첫 실행
  - 역할 선택
  - 어르신 연결 코드 생성
  - 보호자 연결 코드 입력
  - 페어링 완료 후 홈 화면
  - 앱 삭제/재설치 시 동작
- 로그인, 회원가입, 비밀번호, refresh token, 계정 복구를 MVP 범위에서 제외한다.
- 기기 기반 식별 정책을 확정한다.
  - install id 생성 방식
  - device access token 발급 여부
  - 로컬 저장소 삭제 시 재등록 정책
- 보호자 1명/여러 명, 어르신 1명/여러 명 연결 범위를 결정한다.
- 기존 문서와 티켓에서 user/auth 기반 표현을 새 계약에 맞게 정리한다.

## 완료 조건

- README 또는 docs에 로그인 없는 페어링 MVP 흐름이 명확히 적혀 있다.
- 개발자가 API와 Android 화면을 구현할 때 해석이 갈리지 않는다.
- MVP에서 하지 않을 계정 기능이 명확히 분리되어 있다.
- 기존 로그인 기반 티켓과 충돌하는 요구사항이 제거되어 있다.
