# 어르신(Senior) UI 설계

## 설계 원칙

- **화면 수 최소화**: 뎁스 1단계 이내, 뒤로가기 거의 없음
- **텍스트 크기**: 최소 20sp, 주요 요소 28sp 이상
- **터치 영역**: 최소 64dp
- **고대비**: 배경 흰색 / 텍스트 검정 기준
- **한 화면 한 행동**: 화면마다 핵심 액션 1개
- **불안 유발 최소화**: "감시"보다 "안부 확인" 표현 사용

## 색상

| 용도 | 색상 | 비고 |
|------|------|------|
| 배경 | `#FFFFFF` | 순백 |
| 주요 텍스트 | `#111111` | 거의 검정 |
| 보조 텍스트 | `#555555` | |
| 활성 상태 | `#1A8A1A` | 활동 모니터링 실행 중 |
| 비활성 상태 | `#888888` | 서비스 꺼짐 |
| 주의 상태 | `#D97706` | 업로드 실패/확인 필요 |
| 주요 버튼 배경 | `#1A6FCC` | 파랑 |

## 네비게이션 구조

```text
[역할 선택 / 어르신 등록]
   │
   └──▶ [홈 - 활동 모니터링]
              ├──▶ [오늘의 글]
              └──▶ [연결 코드]
```

뎁스: 최대 2단계

## 화면 명세

### 1. 어르신 등록

```text
┌──────────────────────────────┐
│                              │
│         SeniorSafe           │
│       안부 확인 서비스          │
│                              │
│   ┌──────────────────────┐   │
│   │  어르신 이름           │   │
│   └──────────────────────┘   │
│                              │
│   ┌──────────────────────┐   │
│   │      시작하기          │   │
│   └──────────────────────┘   │
└──────────────────────────────┘
```

동작: device 등록 성공 후 `device_access_token` 저장.

### 2. 홈

앱 실행 후 항상 이 화면. 서비스 상태와 마지막 기록 상태가 한눈에 보여야 한다.

```text
┌──────────────────────────────┐
│  안녕하세요, 홍길동님           │
│                              │
│   ┌──────────────────────┐   │
│   │                      │   │
│   │    ●  안부 확인 중    │   │
│   │                      │   │
│   │   휴대폰 사용 기록을   │   │
│   │   보호자에게 알려드려요 │   │
│   │                      │   │
│   └──────────────────────┘   │
│                              │
│   마지막 기록                 │
│   오늘 오전 8:30              │
│                              │
│   전송 상태                   │
│   모든 기록 전송 완료          │
│                              │
│   오늘의 글                   │
│   "오늘도 천천히, 건강하게"    │
│                              │
│   ┌──────────────────────┐   │
│   │    오늘의 글 보기      │   │
│   └──────────────────────┘   │
│                              │
│   ┌──────────────────────┐   │
│   │    서비스 끄기         │   │
│   └──────────────────────┘   │
│                              │
│   ┌──────────────────────┐   │
│   │    연결 코드 보기      │   │
│   └──────────────────────┘   │
└──────────────────────────────┘
```

상태별 변화:

| 상태 | 원형 색상 | 텍스트 | 버튼 |
|------|----------|--------|------|
| 서비스 ON | `#1A8A1A` 초록 | 안부 확인 중 | 서비스 끄기 |
| 서비스 OFF | `#888888` 회색 | 안부 확인 꺼짐 | 서비스 켜기 |
| 업로드 실패 | `#D97706` 주황 | 전송 대기 중 | 다시 보내기 |

### 3. 오늘의 글

어르신이 앱을 자연스럽게 열 수 있도록 매일 하나의 짧은 콘텐츠를 제공한다. 콘텐츠는 명언, 좋은 글귀, 성경 말씀/불교 말씀 등으로 확장 가능하지만, MVP에서는 종교색을 강제하지 않는 "오늘의 글" 표현을 기본으로 한다.

```text
┌──────────────────────────────┐
│  ←  뒤로                     │
│                              │
│       오늘의 글               │
│                              │
│   천천히 걸어도 괜찮습니다.    │
│   오늘도 건강하게              │
│   하루를 시작해보세요.         │
│                              │
│   ┌──────────────────────┐   │
│   │      잘 읽었어요       │   │
│   └──────────────────────┘   │
│                              │
└──────────────────────────────┘
```

동작:

- 매일 저녁 8시에 로컬 푸시를 보낸다.
- 푸시를 탭하면 앱이 열리고 오늘의 글 화면으로 이동한다.
- 앱이 열리면 일반 잠금해제/앱 사용 흐름과 별개로 `last_seen_at` 또는 앱 열람 이벤트를 기록할 수 있다.
- 콘텐츠를 읽은 시각은 로컬 DB에 기록한다.
- MVP에서는 서버 없이 앱 내장 콘텐츠로 시작할 수 있고, 이후 서버에서 오늘의 글을 내려받도록 확장한다.

로컬 푸시 예시:

```text
SeniorSafe
오늘의 글이 도착했어요
잠깐 열어보고 하루를 마무리해보세요.
```

### 5. 진단/내역 영역

MVP 검증용 화면에서는 아래 내역을 확인할 수 있어야 한다. 제품 화면에서는 debug build 또는 숨김 진입점으로 분리한다.

```text
┌──────────────────────────────┐
│  최근 기록                    │
│  08:30 잠금해제 기록 전송 완료 │
│  08:20 서비스 heartbeat       │
│  08:00 서비스 시작            │
└──────────────────────────────┘
```

표시 대상:

- 서비스 시작/중지
- service heartbeat
- boot completed 이후 재시작 시도
- 잠금해제 감지
- 업로드 성공/실패
- 미전송 이벤트 재시도
- 오늘의 글 로컬 푸시 발송
- 오늘의 글 열람
